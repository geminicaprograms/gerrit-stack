## What the runner does now
- CLI: `--scenarios fix,split` (needs `--push-to`, argparse error otherwise), `--variants natural,nudged`, `-j/--jobs N`, `--rena-token FILE` (default `<plugin>/demo/work/.rena-token`, never printed). Gerrit base / auth prefix / project derived from `--push-to` (`http://localhost:8080/a/demo-plugin` → `http://localhost:8080`, `/a`, `demo-plugin`; nested project names after `/a/` are kept whole).
- No `--scenarios` → legacy single stage, byte-identical (verified: dry-run output `cmp`-equal to the committed runner; record keys/order unchanged; `aggregate_case` entries and `report.md` unchanged when no run has `stage2`).
- `Case` reads `rework:` (fix: `anchor_file`/`anchor_line`/`message`; split: `concerns`/`message`; optional `prompt`) and `nudges:` (`stage1`, `stage2.{fix,split}`) with the existing YAML-subset parser (backslash regexes and `{n}`/`{concerns}` placeholders verified against W2's real block), plus `graders-rework/*.md` with optional `scenario:` frontmatter. Missing block → `case X: …/case.yaml has no 'rework: fix:' block (required for --scenarios fix)`, exit 2 before anything runs.
- `run_stage` is the factored session/grader/chain-metrics step (same file set per stage dir); `run_one` (legacy) and `run_pipeline` both use it.
- Pipeline `<case>@<scenario>-<variant>`: results under `runs/<key>/<arm>/<n>/` with stage-1 files at top level, `stage2/` (trace, hook-trace, chain-metrics, last-message, command.txt, push.log), `review.json`, `gerrit-after.json`, `rework-metrics.json`. Hashtags on both pushes: `bench-<case>-<arm>`, `run-<id>`, `scn-<scenario>-<variant>`, `rep-<n>`.
- Reviewer step: urllib client with Basic auth from the token file (header only, never logged). Target: fix = first stage-1 change (chain order) whose current-revision file list matches `anchor_file`, line = first `anchor_line` match in the base64 `…/files/<path>/content` (fallbacks: most `src/main` files, then largest; line 1); split = largest change (insertions+deletions). POST `/a/changes/<n>/revisions/current/review` with `{"labels":{"Code-Review":-1},"message":"Reviewed as rena","comments":{path:[{line,unresolved:true,message}]}}` — the only vote the runner posts; no `/submit` anywhere (asserted by a test on the source).
- Stage 2: `git config gerrit-stack.host <base>`, `GERRIT_HOST`, stage-1 pushed commits tagged `refs/bench/stage1/<i>`, `review` remote removed, same arm command with the stage-2 prompt (+ `\n\n` + nudge for nudged), scenario-filtered rework graders.
- Second push: `push_workspace_for_review_ex` rebases onto `merge-base review/master HEAD` when the histories are related (else the fixture root), parses `[NEW]`/`[UPDATED]` lines, and the runner also queries `hashtag:` for the definitive list (with `CURRENT_REVISION`, `CURRENT_COMMIT`, `DETAILED_LABELS`, `DETAILED_ACCOUNTS`, `MESSAGES`) plus `/comments` per change → `gerrit-after.json`.
- `rework-metrics.json` per contract; interdiff is patch-vs-patch on the `+`/`-` lines only (rebase-aware), descendants/ancestors from stage-1 chain order, `split_equivalent` compares the range diff signature, `reply_posted`/`vote_posted` count non-rena, non-autogenerated activity after the review timestamp. Extra informative keys: `lost_change_ids`, `interdiff_by_change`, `stage2_push_error`.
- Guardrails per stage: hook trace when it has lines else trace heuristics (collect.py's), `bad_outcomes` from Bash commands of every arm (`no_verify_used`, `amend_m_used`, `force_push_attempted`, `topic_used_unasked`, `refs_heads_push_attempted`), `commit_without_change_id` (chain-metrics), `refs_heads_moved` (`../remote.git` master), `gerrit_master_moved` (`/projects/<p>/branches/master` before/after each session).
- Aggregate: entry name = pipeline key + `baseCase`/`scenario`/`variant`; run record = stage-1 keys + `stage2`, `review`, `rework`, `guardrails`, `pipelineCostUsd`, `pipelineDurationSeconds` (+ `stage1Chain`, `pushError`). `byArm` gains `stage2Score`/`stage2PassRate`/`pipelineCostUsd` only when a stage 2 exists; `report.md` and the stdout summary add stage-2 score / pipeline cost columns and a "Rework and guardrails" table only then.
- `-j N`: `ThreadPoolExecutor` per arm over (pipeline, n); `spent` and the cost ceiling under a lock; log lines prefixed `key/arm/n`; results appended in `n` order so the shape equals serial. Cost ceiling counts the whole pipeline (`pipelineCostUsd`).
- `--dry-run` prints, per pipeline and run: fixture, stage-1 command, push-1 refspec with hashtags, the reviewer step (target rule + message), stage-2 setup + command (nudge included), push-2/read-back query.

## Open issues / notes for the batch
